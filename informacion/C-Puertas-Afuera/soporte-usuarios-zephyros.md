# Soporte a Usuarios de Zephyr OS

Zephyr OS, al ser un proyecto de la Linux Foundation, cuenta con un ecosistema de soporte diverso que abarca desde canales comunitarios gratuitos hasta servicios comerciales ofrecidos por empresas miembro. A continuación se documentan las opciones disponibles para usuarios y desarrolladores.

---

## 1. Soporte Comunitario

### 1.1 Discord

El servidor oficial de Discord del Proyecto Zephyr es el **canal de chat primario** utilizado por desarrolladores, contribuidores y usuarios del RTOS. El servidor incluye múltiples canales temáticos para diferentes arquitecturas, boards, y tópicos de desarrollo.

- **Enlace**: [Zephyr Discord Server](https://discord.com/invite/zephyr-888818750588092488)
- **Fuente**: [Zephyr Project Community Page](https://www.zephyrproject.org/community/)

> **Nota**: Según la documentación oficial, el servidor Discord es el foro de chat principal usado por los desarrolladores de Zephyr, donde usuarios y contribuidores pueden hacer preguntas y recibir respuestas de los ingenieros que escribieron el software.

### 1.2 Listas de Correo (Mailing Lists)

El proyecto Zephyr mantiene varias mailing lists públicas para diferentes propósitos:

- **Developer Lists**: Para discusiones técnicas y contribuciones al código
- **Users Lists**: Para preguntas y soporte general
- **Announce Lists**: Para anuncios de nuevas versiones y funcionalidades

Las listas están archivadas públicamente y son consultables. Antes de hacer una pregunta, la documentación oficial recomienda revisar los archivos para ver si la duda ya fue respondida.

- **Fuente**: [Communication and Collaboration — Zephyr Documentation](https://docs.zephyrproject.org/latest/project/communication.html)

El repositorio principal de Zephyr en GitHub ofrece una sección de Discussions donde usuarios pueden hacer preguntas, compartir proyectos, y solicitar características.

- **Repositorio**: [zephyrproject-rtos/zephyr](https://github.com/zephyrproject-rtos/zephyr)

### 1.4 Wiki de GitHub

La wiki del repositorio de GitHub contiene información mantenida por la comunidad, incluyendo:

## 3. Programa de Training Partners (Capacitación Oficial)

El **Zephyr Training Partner Program** es un programa oficial donde miembros Platinum y Silver proporcionan capacitación profesional en Zephyr RTOS. Los training partners ofrecen currículos autorizados por la Zephyr Foundation.

### 3.1 Partners Oficiales

Según la información disponible públicamente:

- **ModularMX**: Training partner oficial que ofrece un currículo autorizado por la Zephyr Foundation
- **Golioth**: Ofrece trainings en vivo mensual y trainings bajo demanda
- **Hacod**: Proveedor de cursos especializados en Zephyr RTOS

### 3.2 Detalles del Programa

- **Descripción**: Los Zephyr Training Partners son miembros Platinum y Silver que proveen entrenamiento en un entorno profesional
- **Alcance**: El programa ayuda a expandir el acceso a training de alta calidad sobre Zephyr RTOS a nivel mundial

## 6. Servicios de Soporte Comercial de Empresas

A diferencia del soporte comunitario gratuito, existen opciones de soporte comercial para empresas que lo requieran.

### 6.1 Modelo de Soporte Comercial

El modelo de negocio de Zephyr se basa en:

1. **Membresías corporativas**: Las empresas pagan membresía a la Linux Foundation para ser miembros del proyecto y tener voz en la gobernanza
2. **Servicios de soporte**: Empresas como Wind River ofrecen versiones comerciales de Zephyr (Rocket) con soporte técnico dedicado

### 6.2 Wind River Rocket

Wind River ofrece **Rocket** como producto comercial derivado de Zephyr, que incluye:

- Soporte técnico dedicado
- Actualizaciones de seguridad
- Servicios en la nube
- Certificaciones específicas

- **Fuente**: Investigación existente, sección 1.2

### 6.3 Miembros-ofrecen Soporte

Los miembros corporativos como Nordic, Intel, NXP, Renesas y otros ofrecen soporte relacionado con el uso de Zephyr en sus productos específicos de hardware.

## 7. Comparación con Otros RTOS

### 7.1 FreeRTOS y AWS

FreeRTOS, adquirido por Amazon en 2017, tiene integración nativa con **AWS IoT** para conectividad cloud. Esto incluye:

- Bibliotecas AWS integradas
- Soporte de Amazon para usuarios de AWS
- Documentación y tutoriales de AWS

- **Fuente**: [Nabto — ThreadX vs FreeRTOS Comparison](https://www.nabto.com/threadx-vs-freertos-comparison/)

### 7.2 ThreadX y Microsoft Azure

ThreadX fue adquirido por Microsoft y renombrado como **Azure RTOS ThreadX**. Incluye:

- Integración nativa con **Microsoft Azure Cloud**
- Stack de red NetX Duo
- Certificaciones de seguridad (IEC 61508, ISO 26262, DO-178)
- Soporte técnico de Microsoft

- **Fuente**: [Wikipedia — ThreadX](https://en.wikipedia.org/wiki/ThreadX), [Microsoft Azure RTOS](https://techcommunity.microsoft.com/category/iot/discussions/azurertos)

### 7.3 Comparación de Modelos de Soporte

| RTOS | Sponsor/Org | Soporte Cloud | Modelo de Soporte |
|---|---|---|---|
| **Zephyr** | Linux Foundation | No tiene integración cloud nativa | Comunitario + Miembros corporativos + Wind River (comercial) |
| **FreeRTOS** | Amazon (AWS) | AWS IoT integrado | Comunitario + Documentación AWS + SafeRTOS (comercial) |
| **ThreadX** | Microsoft | Azure integrado | Comunitario + Microsoft support + certificaciones |
| **NuttX** | Apache Foundation | No tiene | Comunitario |
| **RIOT OS** | Comunidad | No tiene | Comunitario + Académico |
| **RT-Thread** | Comunidad | MQTT, LwM2M | Comunitario + RT-Thread Studio (gratuito) |

### 7.4 Diferenciadores de Zephyr

En comparación con sus competidores, Zephyr se distingue por:

1. **Gobernanza neutral**: No pertenece a Amazon (FreeRTOS) ni a Microsoft (ThreadX), lo que atrae empresas que quieren evitar vendor lock-in
2. **Training Partner Program oficial**: Un programa estructurado de capacitación con partners autorizados
3. **Soporte multi-vendor**: La diversidad de miembros corporativos (Nordic, Intel, NXP, Renesas) provee soporte para múltiples ecosistemas de hardware
4. **Security Subcommittee dedicado**: Un comité específico para seguridad, algo que no todos los RTOS competidores tienen

## Nota Académica — Fundamentos de SO

**Conceptos de la materia relacionados:**

- **§1.1 — Gestión de recursos y soporte comunitario:** Un SO no es solo código — necesita un ecosistema de soporte. Zephyr demuestra que la gestión de recursos en sistemas embebidos (BLE, power management, secure boot) requiere no solo features técnicas sino también documentación exhaustiva, training partners oficiales, y committees técnicos (TSC, Security Subcommittee). Esto refleja que el "soporte" es parte integral de la gestión del recurso humano: sin comunidad capacitada, حتى el mejor kernel fracasa.

- **§1.4 — Gobernanza y evolución arquitectónica:** El modelo de membresía de Zephyr (Platinum/Gold/Silver) refleja cómo las arquitecturas de SO modernas incorporan governance structures. La neutralidad de la Linux Foundation como "umbrella" evita vendor lock-in — un concepto análogo a cómo UNIX evolucionó con POSIX como layer de neutralidad. Wind River oferecendo "Rocket" como versión comercial de Zephyr ejemplifica el pattern de open-core que many OS projects adoptan.

- **§1.2 — Comunidad como diferenciador (5ª generación):** En la era post-2000, el éxito de un SO depende tanto de su comunidad como de su código. Zephyr tiene 3,000+ contribuidores mientras MOSIX murió por falta de comunidad. Este patrón se ve también en Linux kernel mismo — la comunidad hizo que Linus Torvalds sea tan importante como el código. La documentación oficial de Zephyr con versionsmúltiples y búsqueda integrada evidencia matured thinking sobre cómo users acceden al conocimiento.
